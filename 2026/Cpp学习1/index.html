会妨碍 C++ 代码可移植性的东西

  • 使用平台特性
  • 很多第三方库只在特定的平台上可用，所以说，如果你用了这种库…
  • 使用compilers的特别extensions。会导致你的程序不能被其他编译器编译。
  • 由compiler决定的“implementation-defined behavior”（语言标准未统一规定具体结果，但强制要求‌每个编译器/平台实现必须选定一种确定行为并公开文档说明‌的程序行为；其结果在特定实现下是‌确定且可预测的‌，但跨平台可能不同 。‌‌）

本教程会尽可能避免使用平台特性的代码，让我们的程序可以在任何拥有现代C++编译器的平台上运行。

0.5 对编译器、链接器和库的介绍

编译程序

编译程序需要用C++ compiler，也就是C++编译器。编译器会遍历你程序中的所有代码文件，完成两件重要的任务：语法检查 和 转化代码文件为机器语言指令。这些指令存储在一个称为object file(目标文件) 的中间文件中。目标文件的后缀一般是.o/.obj。

链接文件

链接文件需要用 linker，链接器。链接器会把目标文件和库文件连接起来，生成输出文件，一般是exe可执行文件（不过也可能是一个库文件，如果你设置了的话）。

标准库

C++ Standard Library，“the standard library”。绝大多数的C++链接器默认配置为连接标准库的。
也有第三方库可以用。附录里会教“如何连接第三方库”和“创建自己的库”。

构建 Building

由于（将源代码转换为可执行程序）涉及多个步骤，“构建（building）” 这个术语通常用来指代将源代码文件转换为可运行可执行程序的完整过程。
通过构建生成的具体可执行程序，有时也被称为一个 “构建版本（a build）”。
构建自动化工具：make，build2

0.7 编译你的第一个程序

(并非第一个)

最佳实践

为每个程序创建一个项目。

compile, build, rebuild, clean, and run/start

  • Build（构建）：编译项目中或工作区/解决方案内所有被修改过的代码文件，然后将目标文件链接成可执行程序。如果自上次构建以来没有任何代码文件被修改过，则该选项不执行任何操作。
  • Clean（清理）：删除所有缓存的中间文件（目标文件）和可执行文件，这样下一次构建项目时，所有文件都会被重新编译，并生成一个新的可执行程序。
  • Rebuild（重新生成）：先执行“清理（Clean）”，再执行“构建（Build）”。
  • Compile（编译）：重新编译单个代码文件（无论它之前是否被缓存过）。此选项不会调用链接器，也不会生成可执行程序。
  • Run / Start（运行/启动）：执行先前构建生成的可执行程序。部分 IDE（例如 Visual Studio）会在执行“运行”之前自动先执行一次“构建（Build）”，以确保你运行的是代码的最新版本。而另一些 IDE（例如 Code::Blocks）则只会直接执行已有的可执行文件（而不主动重新构建）。

通用运行时问题

问题解决方案

通用编译时问题

编译错误信息常见原因与解决办法
unresolved external symbol _main缺少 main() 函数 / 拼写错误 / 文件未加入项目
main 已定义 / 多个定义项目中存在多个 main()，只保留一个

end1 未声明把 endl 中的字母 l 误写成数字 1

Visual Studio 相关问题

问：使用 Microsoft Visual C++ 编译时，出现 C1010 致命错误，错误信息类似：
"c:\vcprojects\test.cpp(263) : fatal error C1010: unexpected end of file while looking for precompiled header directive"

（中文含义：在查找预编译头指令时遇到意外的文件结尾）

当 Microsoft Visual C++ 编译器设置为使用预编译头（Precompiled Headers），但你的一个（或多个）C++ 代码文件没有将 #include "stdafx.h" 或 #include "pch.h" 作为该文件的第一行代码时，就会触发此错误。

旧版本的 Visual Studio 使用的是 "stdafx.h" 而不是 "pch.h"，因此如果 pch.h 无法解决问题，请尝试使用 stdafx.h。

请注意，对于包含多个文件的程序，每个 C++ 代码文件都需要以这行代码开头。

问：Visual Studio 给出类似这样的错误：
"MSVCRTD.lib(exe_winmain.obj) : error LNK2022: unresolved external symbol _WinMain@16 referenced in function "int __cdecl invoke_main(void)" (?invoke_main@@YAHXZ)"
（中文含义：无法解析的外部符号 _WinMain@16）

你很可能创建了一个 Windows 图形界面应用程序，而不是控制台应用程序。请重新创建项目，并确保创建时选择的是 Windows（或 Win32）控制台项目。

问：编译程序时，收到一条警告： "Cannot find or open the PDB file"
（中文含义：无法找到或打开 PDB 文件）

这是一个警告，而不是错误，因此不会影响你的程序运行。但它确实很烦人。要解决此问题，请进入 调试（Debug）菜单 → 选项和设置（Options and Settings）→ 符号（Symbols），然后勾选 “Microsoft 符号服务器（Microsoft Symbol Server）”。
