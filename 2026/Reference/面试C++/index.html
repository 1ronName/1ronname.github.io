1. 多态与虚函数（⭐⭐⭐）

什么是多态？C++ 如何实现？

多态就是同一个函数名具有多种状态，或者说一个接口具有不同的行为。

C++ 的多态分为两种：

  • 编译时多态（静态联编）：通过重载和模板实现
  • 运行时多态（动态联编）：通过继承和虚函数实现

虚函数的实现机制是什么？

虚函数通过虚函数表实现。虚函数表包含了该类所有虚函数的地址；在有虚函数的类对象中，其内存空间的头部会有一个虚函数表指针（虚表指针），用来管理虚函数表。

当子类重写父类虚函数时，虚函数表中相应的地址会发生改变，改写成子类这个虚函数的地址。这样用一个父类指针来操作子类对象时，就能指明实际所调用的函数。

参考：《游戏引擎架构》P115、https://zhuanlan.zhihu.com/p/98776075

虚函数调用是编译时还是运行时确定的？

运行时确定，通过查找虚函数表中的函数地址确定。

原帖更正： 此说法不严谨。只有通过指针或引用调用虚函数是运行时确定；通过值调用虚函数编译期就可以确定。

虚函数存在类中还是类对象中（是否共享虚表）？

存在类中。不同的类对象共享一张虚函数表（为了节省内存空间）。

在（基类的）构造函数和析构函数中调用虚函数会怎样？

语法上讲调用没有问题，但从效果上看不能达到多态的目的：

  • 构造函数：先构造父类成分，再构造子类成分。在父类构造期间，子类的特有成分还没有被初始化，此时下降到调用子类虚函数、使用这些尚未初始化的数据，一定会出错。
  • 析构函数：先析构子类成分，进入父类析构函数时，子类特有成分已经销毁，此时无法再通过虚函数实现多态。

参考：《Effective C++》条款 9

C 语言可以实现虚函数机制吗？如何实现？

可以。需要做的工作：手动构造父子关系、创建虚函数表、设置虚表指针并指向虚函数表、填充虚函数表；当虚函数被重写时，还需要手动修改函数指针。

补充考点（社招面经）

  • 虚表在只读数据段（.rodata），虚函数在代码段（.text）
  • 不能声明为虚函数的：普通函数、静态成员函数、内联成员函数、构造函数、友元函数
  • 析构函数必须为虚：否则用基类指针删除派生类对象时只调用基类析构，派生类资源泄漏
  • final 的作用：禁止继承，或禁止重写
  • 虚函数的调用开销；虚函数能否”去虚化”（devirtualization）

2. 内存模型与继承（⭐）

C++ 中类对象的内存模型（布局）是怎样的？

一般遵循以下几点：

  1. 如果有虚函数，虚函数表指针始终存放在内存空间的头部
  2. 除虚函数之外，内存空间按类的继承顺序（父类到子类）和字段的声明顺序布局
  3. 如果是多继承，每个包含虚函数的父类都会有自己的虚函数表，并且按照继承顺序布局（虚表指针 + 字段）；如果子类重写了父类虚函数，会在每一个相应的虚函数表中更新相应地址；如果子类有自己新定义的虚函数或非虚成员函数，也会加到第一个虚函数表的后面
  4. 如果是钻石继承并采用了虚继承，则内存空间排列顺序为：各个父类（包含虚表）、子类、公共基类（最上方的父类，包含虚表），并且各个父类不再拷贝公共基类中的数据成员

参考：https://www.cnblogs.com/yunlambert/p/9876491.html

钻石（菱形）继承存在什么问题，如何解决？

问题：会产生二义性。因为两个父类都会对公共基类的数据和方法产生一份拷贝，对子类来说，读写一个公共基类的数据或调用一个方法时，不知道是哪一个父类的，会导致编译错误。

解决：采用虚继承（父类继承公共基类时用 virtual 修饰），这样只会创造一份公共基类的实例，不会造成二义性。

3. 内存管理：分配与对齐（⭐⭐⭐）

C++ 是如何做内存管理的（有哪些内存区域）？

  1. 堆：使用 malloc / free 动态分配和释放空间，能分配较大的内存
  2. 栈：为函数的局部变量分配内存，能分配较小的内存
  3. 全局 / 静态存储区：存储全局变量和静态变量
  4. 常量存储区：专门用来存放常量
  5. 自由存储区：通过 new 和 delete 分配和释放空间的内存，具体实现可能是堆或者内存池

补充：堆是 C 和操作系统的术语，自由存储区是 C++ 的术语，指的是通过 new/delete 动态分配和释放对象的抽象概念。基本上 C++ 也用堆区实现自由存储，但程序员可以通过重载操作符改用其他内存实现，比如用全局变量做的对象池。

堆和栈的内存有什么区别？

  1. 堆中的内存需要手动申请和手动释放；栈中内存由 OS 自动申请和释放
  2. 堆能分配的内存较大（32 位机器上 4G），栈能分配的内存较小（1M）
  3. 在堆中分配和释放内存会产生内存碎片，栈不会
  4. 堆的分配效率低，栈的分配效率高
  5. 堆地址从低到高，栈由高到低

C / C++ 分别用什么做内存分配和释放？有什么区别？能否混用？

C 用 malloc/free，C++ 用 new/delete。前者是 C 语言的库函数，后者是 C++ 语言的运算符。

对于自定义对象，malloc/free 只进行分配内存和释放内存，无法调用其构造函数和析构函数；只有 new/delete 能完成对象的空间分配和初始化，以及对象的销毁和释放空间。不能混用。

具体区别：

  1. new 分配内存空间无需指定大小，malloc 需要
  2. new 返回类型指针（类型安全），malloc 返回 void*，需强制转换
  3. new 从自由存储区获得内存，malloc 从堆中获取
  4. 对类对象，new 会调用构造函数和析构函数，malloc 不会（核心差异）

什么是内存对齐？为什么要对齐？如何对齐？

为什么：关键在于 CPU 存取数据的效率。为了提高效率，CPU 从内存取数据是按一个固定长度的——比如 32 位机上每次取 32bit（4 字节）。若不进行对齐，要取出两块地址中的数据再做掩码和移位，写入寄存器，效率很低。内存对齐一方面可以节省内存，一方面可以提升数据读取速度。

内容：内存对齐指结构体中的数据成员，其内存地址是否为其对齐字节大小的倍数。

对齐原则：

  1. 结构体变量的首地址能够被其最宽基本类型成员的对齐值整除
  2. 结构体内每一个成员相对于起始地址的偏移量能够被该变量的大小整除
  3. 结构体总体大小能够被最宽成员大小整除
  4. 如果不满足这些条件，编译器就会进行填充（padding）

如何写能省空间：声明数据结构时，把字节对齐的数据依次声明，然后把小成员组合在一起，能省去一些浪费的空间；不要把把小成员参杂声明在字节对齐的数据之间。

参考：《游戏引擎架构》P111

4. 类型转换（⭐⭐）

C++ 有哪些类型转换的方法（关键字），各自有什么作用？

关键字作用限制
const_cast把 const 属性去掉（也可以反过来加）只能用于指针或引用；只能改变对象的底层 const
static_cast隐式类型转换：内置基本数据类型之间互转（enum / struct / int / char / float 等），类层次间的向上、向下转换向下转换不安全（无动态类型检查）；不能转换无关类型（如非基类和子类）的指针；不能作用于包含底层 const 的对象
dynamic_cast动态类型转换：把基类的指针或引用安全地转换成派生类的指针或引用运行时进行安全检查；父类一定要有虚函数，否则编译不通过；指针转换失败返回 NULL，引用转换失败抛 bad_cast 异常
reinterpret_cast将数据的二进制形式重新解释（不改变其值），能力等同 C 风格强制转换可转换任何内置类型、任何指针类型，甚至内置类型转指针；不安全，不到万不得已绝对不用

参考：《C++Primer》P144/730、《Effective C++》条款 27

static_cast 和 dynamic_cast 的异同点？

二者都会做类型安全检查，区别在于：static_cast 在编译期进行类型检查，dynamic_cast 在运行期进行类型检查。后者需要父类具备虚函数，前者不需要。

5. 智能指针（⭐）

C++ 中的智能指针有哪些，各自有什么作用？

智能指针主要解决内存泄漏问题，可以自动释放内存空间——因为它本身是一个类，函数结束时调用析构函数并释放内存。

  • shared_ptr：多个共享指针可以指向相同的对象，采用引用计数机制，当最后一个引用销毁时释放内存空间
  • unique_ptr：保证同一时间段内只有一个智能指针能指向该对象（可通过 move 操作传递）
  • weak_ptr：用来解决 shared_ptr 相互引用时的死锁问题。它对对象是一种弱引用，不增加引用计数；shared_ptr 可以直接赋值给它，它可以通过调用 lock() 获得 shared_ptr

shared_ptr 的实现原理是什么？构造函数、拷贝构造、赋值运算符怎么写？是否线程安全？

实现：通过引用计数机制实现。引用计数存储着有几个 shared_ptr 指向相同对象，当引用计数降到 0 时自动销毁这个对象。

社招补充：完整的结构是原始指针 + 引用计数 + 控制块，控制块在堆上，有且仅有一个。

具体实现：

  1. 构造函数：将指针指向该对象，引用计数置为 1
  2. 拷贝构造函数：将指针指向该对象，引用计数 +1
  3. 赋值运算符：= 左边的 shared_ptr 引用计数 -1，右边的 +1；如果左边的引用计数降为 0，还要销毁其指向的对象、释放内存

线程安全：shared_ptr 的引用计数本身是安全且无锁的（原子操作），但它指向的对象的读写则不是。因此可以说 shared_ptr 不是线程安全的。

更准确的说法：同一个 shared_ptr 多线程读写不安全，不同的 shared_ptr 多线程读写安全。

weak_ptr 既然解决循环引用，为什么不用裸指针？

因为 weak_ptr 绑定到 shared_ptr 之后不会增加引用计数，一旦最后一个指向对象的 shared_ptr 被销毁，对象就会被释放——即使 weak_ptr 还指向它。而裸指针在对象销毁之后会变成悬垂指针（野指针）。

补充（社招面经）

  • enable_shared_from_this：从类内部安全获取指向自己的 shared_ptr，避免产生多个控制块
  • 直接 memcpy 两个 shared_ptr 会未定义行为：引用计数会错乱，可能导致双重释放

6. 关键字（⭐）

const 的作用？指针常量和常量指针？const 修饰的函数能否重载？

  1. const 修饰符用来定义常量，具有不可变性。在类中，被 const 修饰的成员函数不能修改类中的数据成员
  2. 指针常量：该指针本身是一个常量，不能被修改，但指针指向的对象可以被修改；常量指针：该指针指向的对象是一个常量，不能被修改，但指针本身可以修改。这涉及顶层 const（本身是 const）和底层 const（指向的对象是 const）
  3. const 修饰的函数可以重载。const 成员函数既不能改变类内数据成员，也无法调用非 const 成员函数；const 类对象只能调用 const 成员函数；非 const 对象无论是否是 const 成员函数都能调用，但如果有重载的非 const 函数，非 const 对象会优先调用非 const 版本

static 的作用？static 变量什么时候初始化？

分三种情况：

  1. 文件作用域（在 .h/.cpp 中直接修饰变量和函数）：这些变量和函数只在本文件可见，其他文件看不到也无法使用，可以避免重定义问题
  2. 函数作用域（作为局部静态变量）：这个变量是全局的，只会进行一次初始化，不会在每次调用时重置，但只在这个函数内可见
  3. 类的声明中（静态数据成员和静态成员函数）：表示这些数据和函数是所有类对象共享的属性，而非每个类对象独有

初始化时机：static 变量在类的声明中不占用内存，因此必须在 .cpp 文件中定义类静态变量以分配内存。文件域的静态变量和类的静态成员变量在 main 执行之前的静态初始化过程中分配内存并初始化；局部静态变量在第一次使用时分配内存并初始化。

参考：《游戏引擎架构》P111、《C++Primer》12.6、https://blog.csdn.net/hueru/article/details/89504059

extern 的作用？

  • 与 “C” 连用时（extern "C" void fun(int a, int b);）：告诉编译器在编译 fun 这个函数名时按 C 的规则翻译，而不是 C++ 的
  • 作为对函数或全局变量的外部声明：提示编译器遇到此变量或函数时，在其它模块中寻找其定义

其他关键字

关键字作用
explicit标明类的构造函数是显式的，不能进行隐式转换
constexpr明确告诉编译器应该验证（函数或变量）在编译期是否就应该是一个常数，这样编译器可以大胆优化
volatile跟编译器优化有关，告诉编译器每次操作该变量时一定要从内存中真正取出，而不是使用已存在寄存器中的备份
mutable使类中被声明为 const 的函数可以修改类中的非静态成员
auto / decltype都用于类型自动推导。auto 不能用于函数传参和推导数组类型，decltype 可以解决这个问题

7. 左值右值、构造函数、移动语义（⭐）

什么是左值和右值？什么是右值引用？为什么要引入右值引用？

  1. 左值：具有可寻址的存储单元，并且能由用户改变其值的量，比如常见的变量（int、float、class 等）。左值具有持久的状态，直到离开作用域才销毁
  2. 右值：表示即将销毁的临时对象，具有短暂的状态，比如字面值常量 “hello”、返回非引用类型的表达式 int func() 等
  3. 右值引用：必须绑定到右值的引用，通过 && 获得。右值引用只能绑定到即将销毁的对象，因此可以自由地移动其资源
  4. 为什么引入：右值引用是为了支持移动操作而引出的。使用右值引用的移动操作可以避免无谓的拷贝，提高性能。std::move() 可以将一个左值转换为右值引用

社招补充：std::move 的原理只是把左值转换成右值引用，它本身不移动任何东西。

为什么要自己定义拷贝构造函数？什么是深拷贝和浅拷贝？

  1. 为什么：拷贝构造函数定义了当我们用同类型的另一个对象初始化本对象时做了什么。某些情况下如果不自己定义、使用默认的拷贝构造函数，就会出错——比如类里有一个指针，默认拷贝会把指针拷贝过去（两个指针指向同一个对象），那么其中一个对象析构之后这个指针会被 delete，另一个类里的指针就变成了野指针（悬垂指针）
  2. 深拷贝 vs 浅拷贝：浅拷贝只是简单地复制指向某个对象的指针，不复制对象本身，新旧对象共享同一块内存；深拷贝会另外创造一个一模一样的对象，新对象跟原对象不共享内存，修改新对象不会改到原对象

什么是移动构造函数，和拷贝构造函数的区别？

移动构造函数需要传递的参数是一个右值引用，它不分配新内存，而是接管传递而来对象的内存，并在移动之后把源对象销毁；拷贝构造函数需要传递一个左值引用，可能会重新分配内存，性能更低。

完美转发（社招面经）

保持参数的原始类型、值类别、修饰符不变。

8. 内联函数与宏

内联函数有什么作用？有什么缺点？

  1. 作用：使编译器在函数调用点上展开函数，可以避免函数调用的开销
  2. 缺点：可能造成代码膨胀，尤其是递归函数，会造成大量内存开销，exe 太大、占用 CPU 资源。此外内联函数不方便调试，每次修改会重新编译头文件，增加编译时间

内联函数和宏有什么区别？有了宏为什么还需要内联函数？

  1. define 宏命令是在预处理阶段对命令进行替换；inline 是在编译阶段在函数调用点处直接展开函数，节省了函数调用的开销
  2. define 不会对参数的类型进行检查，因此会出现类型安全问题（比如定义 max 命令，传一个整数和一个字符串就会出错）；内联函数在编译阶段会进行类型检查
  3. 使用宏时可能要添加很多括号，比较容易出错

9. 杂项

C++11 的新特性

  1. auto 关键字，自动推断变量类型
  2. nullptr 代替 NULL，可以避免重载时出现的问题（一个是 int，一个是 void*）
  3. 智能指针（三个），对内存进行管理
  4. 右值引用，基于它可以实现移动语义和完美转发，消除两个对象交互时不必要的对象拷贝
  5. lambda 表达式，可以理解为一个匿名的内联函数

不足之处：没有 GC（垃圾回收机制）、没有反射机制等。

指针和引用的区别

  1. 指针本质是一个地址，有自己的内存空间；引用只是一个别名
  2. 指针可以指向其他的对象；引用不能，初始化之后就不能改变了
  3. 指针可以初始化为 nullptr；引用必须被初始化为一个已有对象的引用
  4. 指针可以是多级指针；引用只能是一级

重载、重写和隐藏的区别

  1. 重载：同一个名字的函数具有不同的参数列表（参数类型、个数），根据参数列表决定调用哪一个
  2. 重写（覆盖）：派生类中的函数重写了基类中的虚函数，基类中该函数必须被声明为 virtual，并且返回值、参数列表与基类一致
  3. 隐藏：派生类中的同名函数把基类中的同名函数屏蔽掉了；此时基类函数不能声明为 virtual

delete 和 delete[] 的区别？delete[] 如何知道要 delete 多少次？能否 delete this？

  1. 若是基本类型，delete 和 delete[] 效果一样（系统会自动记录分配的空间然后释放）；对于自定义数据类型（如类）就不行：delete 仅仅释放数组第一个元素的内存空间，且仅调用第一个对象的析构函数，而 delete[] 会调用数组所有元素的析构函数并释放所有内存
  2. 这导致在 new [] 一个对象数组时需要保存数组维度。C++ 的做法是在分配数组空间时多分配 4 个字节专门保存数组大小，这个数据存在分配返回的指针周围，delete[] 时就可以取出这个数，从而知道需要调用析构函数多少次
  3. 在类的成员函数中可以调用 delete this，并且之后还可以调用该对象的其他成员，但有个前提：被调用的方法不涉及这个对象的数据成员和虚函数。（类对象的内存空间中只有数据成员和虚函数表指针，并不包含代码内容，成员函数单独放在代码段）

补充（社招面经）

  • 空类默认生成哪些函数：构造函数、析构函数、拷贝构造函数、拷贝赋值运算符、移动构造函数、移动赋值运算符
  • 空指针调用成员函数会怎样：不涉及数据成员 → 不崩；涉及静态成员 → 不崩；涉及虚函数 → 崩（虚表指针为空）

10. STL（⭐⭐⭐）

STL 各种容器的底层实现？

  1. vector：底层是一块具有连续内存的数组，核心在于长度自动可变。数据结构主要由三个迭代器（指针）完成：指向首元素的 start、指向尾元素的 finish、指向内存末端的 end_of_storage。扩容机制：当前可用空间不足时，分配目前空间的两倍或者目前空间 + 所需新空间（取较大值），容量的扩张必须经过”重新配置、元素移动、释放原空间”的过程
  2. list：底层是一个循环双向链表，链表结点和链表分开独立定义，结点包含 pre、next 指针和 data
  3. deque：双向队列，由分段连续空间构成，每段连续空间是一个缓冲区，由一个中控器控制。需维护一个 map 指针（中控器指针），还要维护 start 和 finish 两个迭代器，分别指向第一个和最后一个缓冲区。deque 可以在前端或后端扩容，这些指针和迭代器用来控制分段缓冲区之间的跳转
  4. stack 和 queue：由 deque 作为底层容器实现，是一种容器配接器，修改了 deque 的接口（也可用 list 作底层）。stack 是 deque 封住了头端的开口（先进后出），queue 是封住了尾端的开口（先进先出）
  5. priority_queue：以 vector 作为底层容器，以 heap 作为处理规则，heap 的本质是一个完全二叉树
  6. set 和 map：底层都由红黑树实现

红黑树是什么？

红黑树是一种二叉搜索树，但多了一个颜色属性。性质：

  1. 每个结点非红即黑
  2. 根节点是黑的
  3. 如果一个结点是红色的，那么它的子节点就是黑色的
  4. 任一结点到树尾端（NULL）的路径上含有的黑色结点个数必须相同

通过以上限制，红黑树确保没有一条路径会比其他路径多出两倍以上，因此是一种弱平衡二叉树。相对于严格要求平衡的平衡二叉树，它旋转次数少，所以对于插入、删除操作较多的情况，通常使用红黑树。

AVL 与红黑树的区别：AVL 树是高度平衡的，频繁的插入和删除会引起频繁的 rebalance（旋转操作），导致效率下降；红黑树不是高度平衡的，是一种折中——插入最多两次旋转，删除最多三次旋转。

STL 各种容器的查找、删除和插入的时间复杂度？

  1. vector：支持随机访问（通过下标），O(1)；无序 vector 查找 O(n)，有序 vector 二分查找 O(log n)；插入在尾部最快、中部次之、头部最慢，删除同理。占用内存较大，二倍扩容可能导致内存浪费，内存不足时扩容的拷贝也会造成较大性能开销
  2. list：不支持随机访问，只能扫描查找 O(n)；插入和删除快，只需调整指针指向。不会造成内存浪费，占用内存较小

    （原帖存疑：有说法认为链表每次插入删除都要分配/释放内存，频繁操作时性能并不好，原帖未验证）

  3. deque：支持随机访问，但性能比 vector 低；支持双端扩容，头尾插入删除很快 O(1)，中间插入删除很慢
  4. set / map：基于红黑树，增删查改近似 O(log n)；红黑树基于链表实现，占用内存较小
  5. unordered_set / unordered_map：基于哈希表，无序。理论增删查改 O(1)（最差 O(n)），实际数据分布是否均匀会极大影响性能

STL 怎么做内存管理？Allocator 次级分配器的原理？内存池的优势和劣势？

  1. 为了提升内存管理效率、减少申请小内存造成的内存碎片问题，SGI STL 采用了两级配置器：
    • 分配空间超过 128B：使用第一级空间配置器，直接用 malloc()、realloc()、free()
    • 分配空间小于 128B：使用第二级空间配置器，采用内存池技术，通过空闲链表管理内存
  2. 次级配置器的内存池技术：每次配置一大块内存，并维护对应的自由链表（free list）。若下次再有相同大小的内存配置，直接从自由链表中拔出；客户端释还小额区块时，由配置器回收到自由链表。配置器共维护 16 个自由链表，放在一个数组里，分别管理 8~128B 不等的内存块。分配时先根据所需空间大小（调整为 8B 的倍数）找到对应链表，拔出第一个可用区块；回收时同样先找到对应链表，插到第一个区块位置
  3. 优势：避免内存碎片（外部碎片），不需要频繁从用户态切换到内核态，性能高效
  4. 劣势：仍会造成一定的内存浪费，比如申请 120B 就必须分配 128B（内部碎片）

push_back 和 emplace_back 的区别？

  • emplace / emplace_back 使用传递来的参数直接在容器管理的内存空间中构造元素（只调用构造函数）
  • push_back 会创建一个局部临时对象，再将其压入容器中（可能调用拷贝构造函数或移动构造函数）

参考：《C++ Primer》P308

STL 的排序用到了哪种算法？

快速排序、插入排序和堆排序：数据量很大时用快排；划分区段比较小时用插入排序；当划分有导致最坏情况的倾向时使用堆排序。（即 introsort）

参考：https://feihu.me/blog/2014/sgi-std-sort/

vector 如何手动释放内存？

  • 比较 hack 的方式：nums = {} —— 既清空元素又释放内存
  • 规范的做法：vector<int>().swap(nums) 或 nums.swap(vector<int>())

11. 工程问题

编译链接原理：从 C++ 源文件到可执行文件的过程？（⭐⭐）

包括四个阶段：预处理、编译、汇编、链接。

  1. 预处理阶段：处理头文件包含关系，对预编译命令进行替换，生成预编译文件
  2. 编译阶段：将预编译文件编译，生成汇编文件（把预处理完的文件进行词法分析、语法分析、语义分析及优化后生成汇编代码）
  3. 汇编阶段：将汇编文件转换成机器码，生成可重定位目标文件（.obj 文件）。汇编器根据汇编指令和机器指令的对照表一一翻译
  4. 链接阶段：将多个目标文件和所需要的库连接成可执行文件（.exe 文件）

参考：https://www.cnblogs.com/dongdongweiwu/p/4743709.html

  • C++ 语法：std::copy(src.begin(), src.end(), dest.begin())；std::copy_n(src.begin(), n, dest.begin())
  • C 风格语法：memcpy(void* dest, const void* src, size_t num)

对象池思想

对于那些需要频繁创建和销毁的对象：首先从对象池中寻找有没有可用的对象，如果没有就创建对象来使用；当一个对象不再使用时，不是把它删除，而是将它设置为不激活的状态并放入对象池中，等待需要使用时再去对象池中寻找并激活它。

设计模式

单例模式（⭐⭐）

保证全局只有唯一一个自行创建的实例对象，并由单例类提供获取这个唯一实例的接口。主要有两种实现：

  1. 懒汉式：用到的时候才会加载，线程不安全，需要加锁
  2. 饿汉式：在 main 函数开始的时候就创建对象，线程安全

C++11 标准之后最佳的选择是 Meyers’ Singleton（属于懒汉式）：它利用局部静态变量在第一次使用时才初始化的特性，并且 C++11 解决了局部静态变量的线程安全问题，是当前最简洁也最高效的实现方式。

工厂模式

用来封装和管理类的创建，终极目的是解耦，实现创建者和调用者的分离。分三种：

  1. 简单工厂：一个工厂生产多种产品，要指定产品的名字进行生产
  2. 普通工厂：将产品生产分配给多个工厂，每个工厂只生产一种产品
  3. 抽象工厂：将产品生产分配给多个工厂，每个工厂可以生产多种产品

12. 算法相关

各种排序算法的原理和时间复杂度？

算法原理时间复杂度
快速排序一轮划分选一个基准值，小于它的放左边、大于的放右边，此时基准值的位置就确定了；接着递归地对左右子序列划分平均 O(nlogn)，最坏 O(n²)
堆排序利用完全二叉树性质构造一维数组（左孩子 2i+1、右孩子 2i+2、父节点 (i-1)/2）。构造最大堆，最大值在根节点，把它和最后一个结点交换，再从剩下 n-1 个结点重构最大堆，重复。求升序用最大堆，降序用最小堆O(nlogn)
冒泡排序从前往后两两比较，逆序则交换，不断重复直到有序O(n²)，最好 O(n)
插入排序类似打牌，从第二个元素开始，把每个元素插入前面有序的序列中O(n²)，最好 O(n)
选择排序每次选择待排序列中的最小值和未排序列的首元素交换O(n²)
归并排序将整个序列划分成最小的等长序列，排序后再合并，再排序再合并，最后合成完整序列O(nlogn)
希尔排序插入排序的改进版，取一个步长划分为多个子序列排序，再合并（如 135 一个序列、246 一个序列）平均约 O(n^1.3)，最好 O(n)，最坏 O(n²)
桶排序将数组分到有限数量的桶里，每个桶再个别排序，最后依次列出平均 O(N+C)，最好 O(N)

如何在一个序列中求前 k 个最大或最小的数？

  1. 基于快排：每轮划分选择一个基准值，函数返回基准值的位置。如果该位置恰好是 K，就是第 K 小的数，0 到该位置的数就是前 K 小数；若返回位置小于或大于 K，再在相应半边递归查找。时间复杂度 O(n)
  2. 基于堆排序：求前 K 个最小的数用最大堆，求前 K 个最大的数用最小堆。以最大堆为例：先维护一个大小为 K 的堆，随后对每一个数，与堆顶的最大元素比较——若比堆顶小则替换堆顶并调整堆，若大于则不管。全部比较完后，堆里维护的就是最小的 K 个数。

    原理：这是一种局部淘汰的思想，尽量把小的数都放在堆中，最后使堆中最大的数也比外界所有数都小

如何尽可能快地移除序列中指定条件的元素，且不改变其他元素的相对顺序（remove_if 的原理）？

比如序列 {1,3,2,5,2,2,6,7} 移除所有的 2。

先找到第一个符合条件的元素的位置，然后从这个位置开始往后扫描，把不符合条件的元素逐个安插到这个位置以及之后的位置，无论是什么元素都直接覆盖（可以用一个指针指向要安插和覆盖的位置，往后步进）。时间复杂度 O(n)。
