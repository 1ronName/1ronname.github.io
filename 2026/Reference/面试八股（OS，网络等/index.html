计算机基础

来源：不羁的游侠《计算机基础》四、操作系统 / 计算机组成 / 计算机网络；**标（补）**的部分为面经实证考点，来自面经整理
权重：操作系统 ≳ 数据结构 > 计算机网络 > 计算机组成（组成原理客户端极少单独问；笔试里 OS 和数据结构的权重比面试更高）

1. 操作系统

进程和线程的区别？（⭐⭐）

  1. 进程是运行时的程序，是系统进行资源分配和调度的基本单位，它实现了系统的并发
  2. 线程是进程的子单位，也称为轻量级进程，它是 CPU 进行分配和调度的基本单位，也是独立运行的基本单位，它实现了进程内部的并发
  3. 一个程序至少拥有一个进程，一个进程至少拥有一个线程，线程依赖于进程而存在
  4. 进程拥有独立的内存空间，而线程是共享进程的内存空间的，自己不占用资源
  5. 线程的优势：线程之间的信息共享和通讯比较方便，不需要资源的切换

进程 / 线程 / 协程 三者的区别？（补）

面经实证：88 场统计里”协程 vs 线程”🔥8，问得不少

进程线程协程
调度者操作系统操作系统用户程序自己（协作式，非抢占）
切换开销最大（切换页表等）大（需陷入内核态）最小（在用户态完成）
资源独立内存空间共享进程内存共享所在线程的资源
能否利用多核能能不能（除非配合多线程）
  • 协程本质是用户态的轻量级线程，调度由用户程序控制，是协作式的——协程自己决定何时让出，不会被强制抢占
  • 切换不需要陷入内核，因此在高并发 IO 密集场景下比线程高效得多
  • 局限：单个线程内的协程无法并行利用多核

什么是死锁？死锁的条件以及如何防止？什么是银行家算法？（⭐⭐）

定义：多个进程并发执行，在各自占有一定资源的情况下，希望获得其他进程占有的资源以推进执行，但是其他进程同样也期待获得另外进程的资源，大家都不愿意释放自己的资源，从而导致了相互阻塞、循环等待，进程无法推进。

四个必要条件：

  1. 互斥条件：一个资源每次只能被一个进程使用
  2. 请求并保持条件：因请求资源而阻塞时，对已获得的资源保持不放
  3. 不剥夺条件：在未使用完之前不能被剥夺，只能自己释放
  4. 循环等待：若干进程之间形成一种头尾相接的循环等待资源关系

三种处理方式：

  1. 死锁预防：打破四个死锁条件
  2. 死锁避免：使用算法来进行资源分配，防止系统进入不安全状态，如银行家算法
  3. 死锁检测和解除：抢占资源或者终止进程

银行家算法：一种最有代表性的避免死锁的算法。在避免死锁的方法中允许进程动态地申请资源，但系统在进行资源分配之前，应先计算此次分配资源的安全性——若分配不会导致系统进入不安全状态则分配，否则等待。

安全状态：指存在一个进程序列 {P1, P2, … Pn}，对于每一个进程 Pi，它以后尚需要的资源不大于当前资源剩余量和其余进程所占有的资源量之和。

锁机制：悲观锁与乐观锁（补）

面经实证：88 场统计里”锁机制（死锁/悲观锁/乐观锁）”🔥5

  • 悲观锁：假设冲突总会发生，操作前先加锁，操作完释放。适合写多读少的场景
    • 例：数据库的行锁、SELECT ... FOR UPDATE
  • 乐观锁：假设冲突很少发生，操作时不加锁，提交时校验数据有没有被改过。适合读多写少
    • 实现方式：版本号机制（读时记下 version，写时比对，不一致则重试）、CAS
  • CAS（Compare And Swap）：比较并交换，是乐观锁的实现基础——读取内存值，比较是否等于预期值，相等才写入新值。由 CPU 指令保证原子性
    • ABA 问题：值从 A 改成 B 又改回 A，CAS 检查不出来。解决：加版本号

用户态与内核态（补）

面经实证：字节二面追问过（”既然用了异步加载，懂不懂系统操作？比如用户态内核态”）

为什么要划分：限制不同程序的访问能力——防止程序随意获取其他程序的资源，防止程序写坏系统。

用户态内核态
权限只能受限地访问内存，不允许访问外围设备可以访问内存的所有数据，包括外围设备（硬盘、网卡等）
占用 CPU资源可以被剥夺可以剥夺其他程序的 CPU

切换的三种方式：

  1. 系统调用（主动）：用户程序需要操作系统帮忙完成自己做不了的事，如 IO 操作
  2. 异常（被动）：如缺页异常
  3. 外围设备中断（被动）：如硬盘读写完成

切换的开销：需要保存当前程序的现场（寄存器等状态），再恢复另一个程序的现场，所以频繁切换是有代价的。

操作系统如何管理内存？什么是虚拟内存？

通过一种分页管理机制来进行内存管理。分页管理机制将程序的逻辑地址划分为固定大小的页，而物理内存划分为同样大小的帧。程序加载时，可以将任意一页放入内存中任意一个帧，这些帧不必连续，从而实现了离散分离。

虚拟内存基于分页存储管理机制：它允许程序不必将所有的页都放入内存中，而只是将一部分页映射到内存，另一部分页放在外存上（如磁盘、软盘、USB）。当引用到不在内存中的页时，系统产生缺页中断，并从外存中调入该部分页进来，从而产生一种逻辑上内存得到扩充的感觉——实际上内存并没有增大。

什么是内存碎片？内存碎片存在于虚拟内存还是物理内存？

采用分区式存储管理的系统，在存储分配过程中产生的、不能供用户作业使用的主存里的小分区，称为”内存碎片”。内存碎片分为内部碎片和外部碎片。

（原帖结论）内存碎片只存在于虚拟内存上。

2. 计算机组成

什么是缓存（Cache）？为什么需要缓存？如何提高缓存的命中率？缓存是不是最快的？（⭐⭐）

  1. Cache 即 CPU 的高速缓冲存储器，是一种用于减少处理器访问内存所需平均时间的部件
  2. 为什么需要：CPU 的计算速度远远大于从 CPU 向内存取数据的速度。如果每次都让 CPU 去内存取数据，会导致 CPU 计算能力的浪费。所以设计了缓存，CPU 通过读写缓存来获取操作数，结果也通过缓存写入内存
  3. 如何提高命中率：
    • 注意程序的局部性原理，在遍历数组时按照内存顺序访问
    • 充分利用 CPU 的分支预测功能，将预测的指令放到缓存中执行
    • 缓存的容量和块长是影响缓存效率的重要因素
  4. 缓存不是最快的，寄存器更快

参考：https://zhuanlan.zhihu.com/p/102293437

什么是缓存一致性？如何保证缓存一致性？

  1. 在多核 CPU 中，每个核有自己的缓存。当两个核进行独自修改自己缓存中的数据时，就可能会造成数据不一致的问题，这就是缓存的一致性问题
  2. 解决方式：一是在总线中加锁，二是采用缓存一致性协议

一个缓存块的大小是多少？读取内存中的字段是读多少数据取多少内存吗？

如果缓存没有命中（即读取一个数据时它不在缓存中），不仅需要把该字（数据）从主存中取出，还需要从主存中将它所在的整个字块一次调入缓存中。

缓存线（块）的长度是 64B。

3. 计算机网络

TCP 和 UDP 的区别？

  1. TCP 是传输控制协议，UDP 是用户数据报协议
  2. TCP 是面向连接的、可靠的数据传输协议，它要通过三次握手来建立连接；UDP 是无连接的、不可靠的数据传输协议，采取尽力而为的策略，不保证接收方一定能收到正确的数据
  3. TCP 面向的是字节流，UDP 面向的是数据报
  4. TCP 只支持点对点；UDP 支持一对一、一对多和多对多
  5. TCP 有拥塞控制机制，UDP 没有

TCP 的三次握手（补）

  1. 第一次：客户端发送 SYN=1, seq=x，进入 SYN_SENT，等待服务端确认
  2. 第二次：服务端收到后，回复 SYN=1, ACK=1, seq=y, ack=x+1，进入 SYN_RCVD
  3. 第三次：客户端收到后，发送 ACK=1, seq=x+1, ack=y+1，双方进入 ESTABLISHED

为什么需要三次，而不是两次？
主要是防止已失效的连接请求报文段突然又传到服务端，造成错误。如果只有两次：一个早已失效的连接请求滞留在网络中，服务端收到后以为客户端又要建立连接，就会直接分配资源并进入连接状态；但客户端并不会理会这个确认，服务端就会一直白白等待、浪费资源。三次握手让服务端在第三次时确认客户端确实想连接。

TCP 的四次挥手（补）

  1. 第一次：客户端发送 FIN=1，表示自己没有数据要发送了，进入 FIN_WAIT_1
  2. 第二次：服务端回复 ACK=1，进入 CLOSE_WAIT（此时连接处于半关闭状态，服务端可能还有数据要发）
  3. 第三次：服务端数据发完后，发送 FIN=1，进入 LAST_ACK
  4. 第四次：客户端回复 ACK=1，进入 TIME_WAIT，等待 2MSL 后彻底关闭

为什么是四次而不是三次？
TCP 是全双工的，需要两个方向各关闭一次。服务端收到客户端的 FIN 后，可能还有数据没有发送完，所以不能立刻关闭，只能先回一个 ACK；等自己的数据发完了再单独发 FIN。因此 ACK 和 FIN 不能合并。

为什么要有 TIME_WAIT（等 2MSL）？
① 保证客户端最后那个 ACK 能到达服务端（若丢失，服务端会重发 FIN，客户端还能响应）；② 让本次连接产生的所有报文段都从网络中消失，避免影响之后的新连接。

IO 多路复用：select / poll / epoll（补）

面经实证：腾讯光子二面直接问过——“select poll epoll 的区别””epoll 有两种触发方式，你讲一下””epoll 之所以高效，最核心的原因是什么”

要解决的问题：一个线程要同时监听多个 IO 事件（比如服务器同时处理上万个连接），不能阻塞在某一个连接上。

selectpollepoll
fd 存储数组（位图）链表红黑树 + 就绪链表
数量限制有（通常 1024）无限制无限制
每次调用需把 fd 集合从用户态拷贝到内核态同 select只拷贝一次（epoll_ctl 注册时）
查找就绪 fdO(n) 轮询O(n) 轮询O(1)，回调直接加入就绪链表
效率连接数少时还行同 select连接数多时优势明显

epoll 两种触发方式：

  • 水平触发（LT，默认）：只要缓冲区还有数据，就会一直通知。编程简单，不容易漏事件
  • 边缘触发（ET）：只有状态发生变化时才通知一次，之后不再重复通知。要求一次把数据读干净（通常配合非阻塞 IO + 循环读），否则会丢数据；效率更高

epoll 高效的核心原因：不需要像 select/poll 那样每次轮询整个 fd 集合——它用红黑树管理注册的 fd，当某个 fd 就绪时由回调机制把它加入就绪链表，epoll_wait 只需返回这个链表里的内容，复杂度 O(1)。

4. 数据结构与算法

什么是哈希表？哈希表的长度为什么要是质数？如何处理冲突？哈希表怎么删除一个元素？

  1. 定义：哈希表是一种根据关键码值直接访问数据的数据结构，它通过把关键码值映射到表中的一个位置来访问元素，以加快查找的速度。这个映射函数叫做哈希函数
  2. 长度为什么用质数：可以降低发生冲突的概率，使哈希后的数据更加均匀；如果使用合数，可能会导致很多数据集中分布到一个点上，造成冲突
  3. 解决冲突的办法：开放定址法（包括线性探测、平方探测法）和拉链法
  4. 怎么删除：线性探测法并不会真正删除一个元素，而是做一个标记，否则可能会导致正常的查找出错

参考：https://zhuanlan.zhihu.com/p/144296454
